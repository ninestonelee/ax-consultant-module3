핵심 흐름이 끝까지 갑니다

입력 화면에서 값을 넣고 제출하면 결과가 화면에 나옵니다. 중간에 멈추거나 새로 고침을 해야 하면 아직 완성이 아닙니다. 기능 세 개가 반쯤 되는 것보다 한 개가 끝까지 되는 쪽이 점수가 높습니다.

배포 링크가 어디서나 열립니다

내 PC에 있는 파일이 아니라 인터넷 주소로 엽니다. 강의장 와이파이를 끄고 휴대폰 데이터로 열어도 같은 화면이 나와야 합니다. 15시 시연에서 강사진이 이 주소를 직접 엽니다.

가상 데이터라는 표시가 있습니다

초기 데이터(미리 넣는 예시 자료) 10행이 들어 있고,
맨 아래에 '가상 데이터 · 교육용 시범'이라는 문구가 보입니다. 지어낸 값이 실제 값처럼 보이면 제안서 전체를 믿기 어려워집니다.

4

저장소만 봐도 지금 상태를 압니다

저장소에 index.html과 README.md, TODO.md가 있고 TODO.md에 지금 버전, 남은 일, 테스트 건수가 적혀 있습니다. 처음 보는 사람도 README.md만 읽고 쓸 수 있어야 합니다.

세션 6 · 3-4 ③ · 강의 · 초기 데이터

초기 데이터 10행은 케이스 카드의 숫자와 맞게 만듭니다

빈 화면으로 시연하면 고객은 쓰는 모습을 떠올리지 못합니다.
어제 사양서(T-4)에 적은 가상 데이터 10행을 넣되, 근거로 삼은 문서의 숫자와 어긋나지 않게 합니다.

만드는 규칙 네 가지

•

가상 데이터만 넣습니다. 고객사의 실제 거래처, 실제 사람 이름, 실제 단가는 넣지 않습니다.

•

케이스 카드의 숫자와 맞춥니다. 새솔정밀이라면 '견적이 월 60건 이상이고 회신에 3일이 걸린다'는 사실과 어긋나지 않게 날짜와 건수를 정합니다.

•

정상 7행, 경계 3행으로 섞습니다. 납기가 급한 건, 수량이 아주 많은 건, 값이 빈 건 같은 까다로운 경우(경계)를 넣어야 시연에서 판단하는 모습이 보입니다.

•

열 이름은 어제 계획(P-5)에서 정한 구글 시트 열 이름과 똑같이 씁니다. 13시에 시트와 연결할 때 고칠 것 없이 바로 맞습니다.

세션 6 · 3-4 ③ · 강의 · 표시와 휴대폰

시범 표시와 휴대폰 확인, 이 두 가지가 시연 사고를 막습니다

기능보다 사소해 보이지만 강사진 눈에 바로 띄는 것들입니다.
집중 제작의 셋째, 넷째 단계에서 검증자가 아래 항목을 하나씩 확인합니다.

화면 맨 아래 표시 — '가상 데이터 · 교육용 시범'

•

모든 화면의 맨 아래에 같은 문구가 보입니다. 첫 화면에만 있고 결과 화면에 없으면 안 됩니다.

•

글자가 배경색에 묻히지 않고, 휴대폰에서도 읽을 수 있는 크기입니다.

•

초기 데이터 표나 목록 가까이에도 '가상'이라는 말이 한 번 더 있으면 좋습니다.

•

이 표시는 지침 파일 넷째 줄의 규칙입니다. 빠졌다면 AI가 규칙을 놓친 것이니 지침 파일이 연결됐는지도 봅니다.

•

제안서에 화면을 캡처해 넣을 때도 이 표시가 같이 찍히게 합니다.

휴대폰 확인 — 고객은 휴대폰으로 엽니다

•

입력 칸이 화면 폭 안에 들어오고, 옆으로 밀어야 보이는 칸이 없습니다.

•

제출 버튼이 엄지로 누를 수 있는 크기이고 화면 밖으로 나가지 않습니다.

•

표가 길면 화면 안에서 위아래로 넘겨 보거나 카드 모양으로 바뀝니다.

•

숫자 칸을 누르면 숫자 자판이 뜹니다. 안 뜨면 TODO.md에 적고 넘어갑니다.

•

새 버전을 올린 뒤에는 휴대폰에서 새로 고침을 해 옛 화면이 남아 있지 않은지 봅니다.

핵심

두 가지 모두 지침 파일에 이미 적혀 있는 규칙입니다. 지시문에 다시 쓰지 말고 AI가 지침 파일을 지켰는지만 확인합니다.

세션 6 · 3-4 ③ · 절차 · 다시 올리기

고친 파일을 다시 올려도 배포 링크는 그대로입니다

어제 'Hello 고객사'를 올릴 때와 같은 순서입니다.
저장소에 같은 이름의 index.html을 다시 올리면 주소는 바뀌지 않고 내용만 새 버전으로 바뀝니다.

1

폴더에서 최신 버전 찾기

04_MVP 폴더에서 버전 번호가 가장 높은 파일을 찾습니다. 올릴 파일의 이름은 index.html이어야 합니다. 버전 번호가 붙은 파일은 복사한 뒤 이름을 바꿉니다.

2

저장소에 올리기

GitHub 저장소 화면에서 Add file, Upload files를 차례로 누르고 index.html과 TODO.md를 끌어다 놓습니다. 이름이 같으면 새 파일로 바뀝니다.

3

변경 내용 한 줄 적기

Commit changes 칸에 'v4 견적 초안 표 추가'처럼 무엇을 바꿨는지 한 줄 적고 확정합니다. 이 한 줄이 저장소에 기록으로 남습니다.

4

새 화면이 떴는지 확인

잠시 뒤 배포 링크를 휴대폰에서 새로 고침합니다. 옛 화면이 보이면 1~2분 기다렸다가 다시 엽니다.

증상

먼저 볼 것

새로 올렸는데 옛 화면이 그대로 보인다

휴대폰과 PC에서 새로 고침하고 1~2분 뒤 다시 엽니다. 저장소의 index.html이 방금 올린 시각인지 봅니다

링크를 열면 '찾을 수 없음'이 나온다

파일 이름이 index.html인지(대문자, 띄어쓰기, v번호가 없는지), 폴더 안이 아니라 저장소 첫 화면에 있는지

폴더 연결이 안 되어 파일이 폴더에 없다

입구 ②(대화창에서 받기)로 바꿉니다 — 전체 코드를 받아 메모장에 붙여 index.html로 저장

기록

올릴 때마다 TODO.md의 '지금 버전' 줄을 고칩니다. 저장소 주소와 배포 링크는 10시 50분까지 바뀌지 않습니다.

왜 지금 적습니까

•

세션 6 · 3-4 ③ · 강의 · 완주 안전장치

10:25에 핵심 기능이 안 되면 세 가지 길로 끝까지 갑니다

판정은 벌점이 아니라 길 안내입니다. 강사가 팀을 돌며 '핵심 기능이 지금 끝까지 되는가' 하나만 묻고, 안 되면 아래 순서대로 길을 고릅니다.

1

기능을 2개로 줄이기

먼저

기능 세 개 가운데 가장 덜 된 하나를 뺍니다. 뺀 기능은 과제 정의서의 '하지 않을 일' 칸과 TODO.md의 '다음에'에 한 줄로 적습니다. 대부분의 팀은 이것으로 풀립니다.

2

예비 시제품 고쳐 쓰기

그래도 어려우면

강사가 준비한 예비 시제품을 내 저장소로 복사(포크)해 우리 고객사의 이름, 칸 이름, 초기 데이터로 바꿉니다. 새로 만드는 대신 고쳐 쓰는 길이고, 저장소와 배포 링크는 똑같이 남습니다.

3

시연 화면부터 올리기 (C안)

시연 화면이 급하면

ChatGPT Sites나 Claude 아티팩트로 시연용 화면을 먼저 올립니다. 저장소는 나중에 채우고, 제출 시트에 'C안'이라고 적습니다.

길

남는 결과물

제안서에 적는 한 줄

기능을 2개로 줄이기

배포 링크 + 저장소 (원래 조건 그대로)

'셋째 기능은 이번에 하지 않고 확대 단계별 계획 1단계에 넣었다'

예비 시제품 고쳐 쓰기

배포 링크 + 저장소 (예비 시제품을 복사해 고침)

'강사가 준 예비 시제품을 고객사 데이터에 맞게 고쳤다'

시연 화면부터 올리기

Sites 또는 아티팩트 링크 (저장소는 나중에 채움)

'시연 화면은 임시로 올린 것이고 저장소는 나중에 채운다'

핵심

어느 길로 가도 13시 자동화, 14시 효과 측정과 제안서, 15시 시연에 그대로 참여합니다. 숨기지 않고 적는 팀이 점수를 지킵니다.
