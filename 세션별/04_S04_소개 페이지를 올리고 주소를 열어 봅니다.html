세션 4 · 3-4 ① · 시범

첫날 쓴 코치 웹앱은 index.html 파일 하나입니다

AX 사업계획서 코치를 강사 화면에 띄워 놓고 파일을 직접 열어 봅니다. 화면, 꾸밈, 동작이 한 파일 안에 모두 들어 있습니다.

1

화면도 동작도 한 파일

글과 단추(HTML), 색과 배치(CSS),
눌렀을 때의 동작(JavaScript)이
index.html 하나에 들어 있습니다. 파일을
더블클릭하면 브라우저에서 바로 열립니다.

2

설치할 것이 없습니다

따로 깔 프로그램도, 우리가 운영할 서버도
없습니다. 파일을 받은 사람은 브라우저만
있으면 됩니다. 그래서 메일로 보내도 되고
링크로 올려도 됩니다.

3

AI 답은 밖에서 옵니다

파일 안에는 AI가 들어 있지 않습니다.
코치 웹앱을 claude.ai 안에서 열면
Claude가 답했고, 파일만 따로 열면
ChatGPT에 복사해 붙이거나 본인
API 키를 넣는 방식 가운데 골랐습니다.

오늘 우리가 만들 것도 같은 모양입니다

•

AI에게 말로 시켜 index.html 한 파일을 받습니다. 코드를 읽을 줄 몰라도 됩니다. 열어 보고, 눌러 보고, 틀린 곳을 말로 고칩니다.

•

받은 파일을 GitHub에 올리면 주소가 생깁니다. 그 주소가 네 가지 결과물의 '배포 링크'이고, 파일이 올라간 곳이 '저장소'입니다.

같은 API 키라도 어디에 적어 두느냐에 따라 위험이 달라집니다

API 키는 AI 사용 요금이 붙는 비밀번호입니다. 진단 코치 화면에 넣을 수 있었던 키와 코드에 적힌 키는 자리가 전혀 다릅니다.

내 브라우저에 저장한 내 키 (진단 코치의 방식)

•

본인이 직접 키를 넣고, 그 키는 그 브라우저 안에만
남습니다.

•

파일(index.html)에는 키가 적혀 있지 않습니다. 파일을 남에게
줘도 키는 따라가지 않습니다.

•

쓴 만큼의 요금은 키 주인 본인에게만 청구됩니다.

•

조심할 점: 같은 PC와 브라우저를 쓰는 사람은 볼 수 있습니다.
공용 PC에서는 넣지 않고, 다 쓰면 지웁니다.

코드와 공개 저장소에 적힌 키 (하면 안 되는 방식)

•

키가 파일 안에 글자로 적혀 있습니다. 페이지를 여는 누구나
'소스 보기'로 읽을 수 있습니다.

•

공개 저장소에 올리는 순간 검색되고 수집됩니다. 지워도
기록(커밋 이력)에 남습니다.

•

남이 그 키로 AI를 쓴 요금이 키 주인에게 청구됩니다.

•

이미 올렸다면 파일에서 지우는 것으로 끝나지 않습니다.
그 키를 없애고 새로 발급받아야 합니다.

주의

우리 시제품은 공개 저장소에 올라갑니다. 그래서 코드에는 어떤 키도, 비밀번호도, 실제 고객 정보도 넣지 않습니다.

핵심

키는 화면 파일(index.html)에 적지 않습니다. 필요하면 서버 쪽(구글 Apps Script)에만 둡니다.
