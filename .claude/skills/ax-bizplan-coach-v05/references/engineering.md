# 제조AI의 설비·데이터·일정·사업비를 연결하는 방법

사업계획의 문장 하나를 발주 근거와 현장 시험으로 이어갈 수 있게 작성한다. 프로젝트 ID는 예측의 정확도가 아니라 범위·책임·비용의 연결을 보존하는 데 쓴다. 아래 대장에는 받은 사실을 먼저 넣고, 설계 제안과 아직 받을 근거는 별도 열로 적는다.

## 기술 범위와 구매 근거

요구→공정→설비/위치→신호·연계→기능→작업→비용→인수시험을 [delivery-links.csv](../assets/submission/delivery-links.csv)에 연결한다. 행의 기준은 하나의 납품 가능한 기능 또는 인터페이스이다. 공유 서버처럼 여러 행에 연결되는 비용은 ‘비용 ID’ 하나로 지출 원장에만 계상한다. 요구사항을 지우거나 수량을 바꾸면 영향받는 행, 대시보드, 예산, 인수시험을 함께 점검한다.

- 현장 배치에는 기존/신규, 설비 태그, 물리 위치, 센서 채널과 계기 단위, 측정/제어 가능 여부, 설치·검교정 제약, 자산대장 또는 사진 ID를 표시한다. 설비 수가 곧 신규 센서 수는 아니다. 회로 통합·공용 부하와 계측 채널 수를 확인해야 BOM 수량을 결정할 수 있다.
- 물리 구성은 설비/계기, 현장 단말, 통신 경로, 저장 서버, 작업자 단말의 경계를 그린다. 논리 구성은 ‘수집→저장→로트 연결→판정→경보→현장 확인/조치→성과 집계’처럼 정보의 흐름을 표시한다. 통신 방식·운영 주체·인증·장애 시 버퍼링과 복구 책임을 인터페이스마다 적는다. 실측 도면이 없으면 제목을 ‘제안 개념도’로 붙이고 도면 확보자·다음 결정을 적는다.
- 화면 명세는 권한자·업무 동사·입력·검증·출력·수정 이력·조치 기한·수동 대체로 작성한다. 기능별 신규/기존/변경 여부를 표시한다. 환경에 없는 시스템과 ‘기존 연계 완료’를 쓰지 않는다.
- 계약/발주에 쓸 수 있는 수량과 단가는 견적·설치 도면·유효기간·세액 포함 여부에서 확인한다. 입력에 없는 숫자를 개략 견적으로 만들어 채우지 않는다. 발주 근거가 없으면 확정 수량·단가·공수 칸을 비우고, 별도 ‘비교용 제안’ 칸에 전제·산식을 붙여 후보별 차이와 추가 확인할 조건을 연결한다. 상세 예는 [현장 결정과 편성](field-decisions.md)에 있다.

## 생산·검사·센서 데이터

[data-dictionary.csv](../assets/submission/data-dictionary.csv)를 공정별로 작성하고, 인터뷰에서 확인한 기존 데이터와 설치 후 수집할 데이터를 분리한다. 로트 합계, 검사 사건, 센서 샘플의 해상도를 명시한다. 서로 다른 단위를 한 행으로 보고 결합하면 학습 건수가 부풀거나 사후 정보가 예측에 들어간다.

대표 시험은 키·시각이 연결되는 경로 하나를 끝까지 실행 가능한 형태로 기술한다. 원천 기록 ID, 설비 ID, 발생/수신 시각과 시간대, 생산 LOT 시작·종료, 품목·교대, 검사/재검·정정/취소를 사용한다. 원천에 없는 키는 ‘추가 수집’이다. 작업구간 경계는 시작 포함/종료 제외 등 한 가지 규칙을 정하고 분할·합병·재작업 때 모로트와 하위 로트 매핑을 남긴다. 생산량은 처음 확정한 제품 단위로 한 번, 적산량은 같은 계기의 유효 차분으로 한 번 집계한다. 리셋·교체·역행은 정상 사용량과 구분한다.

[acceptance.csv](../assets/submission/acceptance.csv)에 동일 로트 중복 전송, 장애 중 누적→복구 재생, 교대 경계, 누락/늦은 검사, 마감 후 정정, 계기 리셋을 독립 시험으로 둔다. 기대값은 사건 ID 중복 제거·원장합과 월보 일치·정정 전후 보존과 같이 확인 가능한 조건으로 쓴다. 표본이 없으면 합성 입력을 만들어 시험 설계·예상 결과를 보여줄 수 있다. 합성 시험 통과를 실제 설치 인수로 기록하지 않는다.

## 모델 후보별 채택과 검수

| 목적 | 필요한 근거 | 적용 판단과 현장 행동 |
|---|---|---|
| 품질 위험 예측 | 예측 당시 이용 가능한 상태, 검사 시각/결함, 정상 검사 사례, 경보 이후 작업 구간 | 추가 검사나 예방 조치의 시점·책임자·대상 수를 정한다. 집계 로트만 있으면 개별 제품/시간창 판정 성능은 미측정이다. |
| 고장 또는 수명 예측 | 실제 고장·정비 사건, 설비 가동시간, 정비로 중단·갱신된 사건의 처리, 경보 선행시간 | 개입 가능 시간과 비용이 확인된 설비부터 선정하고 고장 정답이 없으면 후보/보류로 둔다. |
| 이상 감지 | 정상 운전 상태와 운전모드 변화, 센서 이상/정상 전환, 담당자 확인 결과 | 상태 차이와 고장을 구분한다. 정상만 학습할 수 있어도 경보의 현장 유용성 검증에는 별도 점검이 필요하다. |
| 에너지 예측·관리 | 동일 회로의 실측·생산수량·가동/대기 구분, 바꿀 수 있는 운전 조건 | 조회·경보만으로 감축 실적을 산정하지 않는다. 에너지 예측모델과 관리용 계측 KPI 중 필요한 범위를 정한다. |

주 과제별로 예측 단위·결정 시각·입력 가능 시각·정답 정의, 개입/평가 구간, 라벨 수와 두 클래스 분포, 훈련/조정/최종 시험 기간, 기준 규칙, 비용·보류 조건을 기록한다. 미검사를 정상으로 세지 않는다. 항상 한 클래스만 예측하는 규칙을 동일 표본에서 계산해 본다. 표본이 한 클래스뿐이면 높은 점수가 나와도 실제 경보 성능 판정을 보류한다. 예측 직후의 결과에 작업자 개입이 영향을 준다면 표시 전 관찰 시험과 표시 후 운영 효과를 나눈다.

임곗값·사전처리는 훈련/조정 데이터에서 정하고 마지막 시험 로트에는 재적합하지 않는다. 같은 로트를 통째로 묶어 시간순 분리하고 설비·교대·제품별 미탐·오탐, 경보 선행시간, 점검 소요량과 교대 가용 인력을 확인한다. 분모가 있는 경우에만 혼동행렬에서 정밀도·재현율·F1을 계산한다. 임계 허용치와 최소 시험 표본은 도입·공급사가 검수 전에 합의할 값이다. 표본·응답시간·안전조건 미달이면 기존 점검 유지, 시범 범위 제한, 추가 자료 요청, 재시험 책임과 기한을 함께 적는다.

## 사업비·일정·효과

1. 재원표에서 정부·기업 현금/현물의 적용 조건과 조달 증빙을 연결한다. 지출표에서는 소프트웨어·장비·통신·교육·정산 등 해당 양식 비목별로 구매/개발/인건비를 나눈다. 단위·세금 포함 범위를 통일한다. 구매액은 수량×단가, 인건비는 인별 실제 적용 단가×기간×투입률로 산정한다. 견적, 급여·참여 근거, 비목 적격성은 서로 다른 확인이다. 총액만 있는 경우 지출 미산정과 미배정 재원을 표시하고 균형을 맞추려고 가공 금액을 배분하지 않는다.
2. 작업ID마다 선행작업·착수 조건, 납기·설치 창, 책임자·월별 가용시간, 산출물과 완료 판정을 연결한다. 납기 지연 시험에서 설치·기준 측정·학습·시운전·인수 중 영향을 받는 작업을 명시한다. 현장 담당자가 생산도 겸하면 전체 근무시간에서 교대·본업을 뺀 가용시간을 기준으로 한다.
3. 에너지 효과는 동일 경계·기간·분모에서 목표 원단위 차이×대상 생산량을 구하고, 가능한 조치별 절감량(대기부하 차×줄일 수 있는 시간 등)과 비교한다. 미계측이면 ‘달성 검증 대기’로 남기고 설치 후 변경 전 기준선, 효과 측정 담당과 품질·납기 조건을 정한다.
4. 품질 회피액은 개선 가능한 개수×실제 회피가능 단가, 전력 회피액은 회피 kWh×해당 요율이다. 생산량·제품구성·단가·달성률·추가운영비를 밝히고, 저/기준 시나리오의 기간을 결과에 표시한다. 같은 손실이 품질 단가와 전력 절감 양쪽에 있으면 제거 전에는 합계를 보고하지 않는다. 총사업비와 기업 현금 투자액 중 무엇을 기준으로 투자성을 보는지도 구분한다.
5. 구축 후 운영은 장애 접수→현장 안전 확인·수동 운영→원인·복구→원장 대사→재개 승인으로 기록한다. 서비스 시간·복구 목표·유무상 범위는 협약·보증서 또는 ‘합의 필요’로 표시한다. 데이터 복원과 모델 롤백 책임자를 정하고, 데이터·모델·설비·라이선스에 대한 유지권과 전환 비용을 최종합의 안건에 포함한다.

## 서식 작성 예 · 재전송과 마감 정정

아래 사건은 인수시험을 설계하는 임의의 시험 데이터다. 어느 신청 기업의 실적·수량·단가로도 전용하지 않는다. 설비 한 대가 07:00~08:00에는 로트 A, 08:00~09:00에는 B를 생산했다. 전력량은 시간 구간 양쪽 경계에서 읽은 누적값의 차, 생산수는 로트별 마감 입력값이다.

| 원천 식별자/개정 | 발생 시각 | 내용 | 예상 처리 |
|---|---|---|---|
| 계기 X/a | 07:00 | 누적 100 kWh | A 시작값 |
| 계기 X/b | 08:00 | 누적 104 kWh | A 종료 및 B 시작에 같은 값을 참조함. 08:00 생산 사건은 새 작업구간 B에 속함 |
| A 마감/1 | 08:00 | 명시 로트 A 생산 40개 | 생산 사건과 다른 마감 보고로, 명시한 A에 40개를 반영 |
| A 마감/1 재전송 | 08:04 수신 | 원 이벤트·개정·값 동일 | 수신 건수만 늘고 생산량은 불변 |
| 계기 X/c | 09:00 | 누적 107 kWh | B 종료, A 4 kWh·B 3 kWh |
| B 마감/1 → 마감/2 | 09:00, 사후 승인 | 생산 30개를 28개로 정정 | 감사 이력은 두 버전, 집계에는 최신 승인값 28개만 반영 |

같은 범위의 최종 원장과 화면은 생산 68개·7 kWh여야 한다. 재생 시계의 순서를 바꿔도 승인된 개정번호가 우선한다. 승인 없는 정정, 동일 ID·개정에 다른 값, 경계 한쪽에 계기값이 없는 경우는 각각 검토 대장으로 보낸다. 시각이 맞지 않는 계기값을 임의 배분하고 로트별 실측으로 표시하지 않는다. 이 예를 실제 현장에 적용할 때는 사용자 권한·교대 마감 기준·장비 이벤트 규격을 먼저 합의한다.

## 실행 가능한 검산

[check_delivery.py](../scripts/check_delivery.py)는 Python 표준 라이브러리만 사용한다. 시험 입력 파일을 만들 때, 실제로 받은 값과 합성 시나리오 중 어느 쪽인지 보고서에 표시한다.

- `python3 scripts/check_delivery.py replay scenario.json`은 ISO 시각(UTC 오프셋 포함)의 같은 설비에 대해 시작 포함·종료 제외의 작업 구간, 양 끝 검침값, 최신 승인 마감량을 대사한다. 여러 시각의 적산값이 역행하거나 경계가 누락되면 해당 에너지는 null이다. 같은 ID·개정·수량의 재전송은 합계에서 한 번만 반영한다. 승인 대기·검침 이상 등 보류가 있으면 결과 JSON을 출력하고 종료코드 1을, 모순된 입력에는 2를 반환한다. 정상 종료는 0이다. 연속 구간으로 나눌 수 없는 동시생산, 복수회로 배분 또는 교체가 잦은 계기는 식별자를 구분하고 별도의 승인된 배분 규칙을 먼저 설계한다.
- `python3 scripts/check_delivery.py delay schedule.json --links delivery-links.csv`는 공통 기간 단위로 작성한 선후관계 일정에 지연을 적용해 작업별 완료시점·변화와 연결된 기능·인수시험을 출력한다. 자원 충돌, 교대 달력, 계약상 납기 여유는 별도 공수·가용시간표로 검토한다. 계약된 납기나 확약되지 않은 시간을 이 계산만으로 확정하지 않는다.

최소 재생 입력(JSON, 합성):

