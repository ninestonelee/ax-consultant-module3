# 자료 대장과 결정 대장

사례를 열면 원본을 먼저 보관하고 `manifest.csv`에 자료 ID와 인용 위치를 등록한다. 하나의 문서에서 여러 결정을 뒷받침하는 문단이 멀리 떨어져 있으면 위치별로 자료 ID를 부여한다. 다음으로 `claims.csv`에서 결정마다 필요한 자료와 실제로 인용한 자료를 적는다. 두 대장은 UTF-8 CSV이며 UTF-8 BOM도 읽을 수 있다.

## 실행

스킬 폴더에서 사례 폴더를 인수로 전달한다. 대장 이름을 바꾼 경우 두 번째 명령처럼 사례 폴더 기준 상대경로를 지정한다. Python 3.9 이상에서 추가 패키지 없이 실행한다.

```sh
python3 scripts/check_evidence.py "/작업/사례"
python3 scripts/check_evidence.py "/작업/사례" --manifest 자료/원본.csv --claims 결정/판단.csv
```

성공은 종료 코드 0이다. 표준 출력의 JSON에 확정 수 `confirmed`, 보류 수 `hold`, 보류 사유와 미충족 ID 목록 `held`, 대장별 SHA-256을 담는다. 보류만 있는 사례도 대장 기록이 적절하면 성공한다. 종료 코드 1이면 JSON의 `error`에 표시된 ID 또는 대장 행을 확인한다.

## 자료 대장

| 열 | 작성 방법 |
|---|---|
| `evidence_id` | 사례 안에서 유일한 자료 ID. 공백과 세로줄은 사용할 수 없다. |
| `kind` | 실제 수령 원본 `actual`, 연습·역할극 자료 `synthetic`, 구해야 할 자료 `missing` 중 하나. 실제 자료는 제공 주체와 전달 경위를 먼저 확인한다. |
| `path` | 원본 파일의 사례 기준 상대경로. `missing`이면 빈칸. |
| `sha256` | 원본 파일 바이트 전체의 SHA-256 64자리. BOM과 줄바꿈도 지문에 포함한다. `missing`이면 빈칸. |
| `locator` | `line:4`, `lines:4-6`, `text:고유한 정확한 원문` 중 하나. 번호는 CSV 헤더·빈 줄을 포함한 물리 행이며 1부터 센다. `missing`이면 빈칸. |
| `issuer` | 실제 자료 제공처, 합성 자료 작성 주체 또는 미수령 자료 요청처. |
| `required_for` | 선택 열. 이 자료가 반드시 필요한 결정 ID를 기입한다. 여러 값은 `|`로 연결한다. 결정 대장에서 의존 자료 자체를 빼는 변경을 탐지하려면 검토 초기에 이 열을 채우고 대장을 동결한다. |

이 검사기가 직접 인용 위치를 대조하는 형식은 UTF-8 텍스트·마크다운·CSV 등이다. 스캔이나 서식 파일을 받을 때는 원본 파일과 지문을 따로 보관하고, 페이지·표·셀 위치와 확인자가 명시된 전사본을 연결한다. 전사 내용과 원본 대조를 마치기 전에는 관련 결정을 보류한다. 인용 위치는 원본 내용을 검토할 수 있을 만큼 좁게 지정한다.

## 결정 대장

| 열 | 작성 방법 |
|---|---|
| `claim_id` | 사례 안에서 유일한 결정 ID. |
| `decision` | 판단 주제. 승인·날인·확약·견적 확정은 `approval`, 참석·등록·배치는 `identity`, 권리·귀속은 `ownership`을 쓴다. 나머지는 예산, KPI, 검수 등 현장 용어로 작성한다. |
| `status` | 이 범위에서 확인한 내용은 `confirmed`, 필요한 자료나 판단이 남아 있으면 `hold`. |
| `scope` | 실제 현장 판단은 `actual`, 연습용 입력으로 내린 판단은 `simulation`. 계획서에서 같은 범위를 표시한다. |
| `statement` | 한 행에 한 판단을 적는다. 보류 시 사유나 다음 확인 조건을 쓴다. |
| `required_evidence_ids` | 그 결정을 내리려면 필요한 모든 자료 ID. 여러 값은 `|`로 구분한다. 미수령 자료도 자료 대장에 등록한 뒤 포함한다. |
| `evidence_ids` | 판단 과정에서 인용한 자료 ID. 보류 행은 비워 둘 수 있다. 요청한 항목의 상태를 인용해도 해당 자료를 수령하기 전에는 의존 조건이 열린 상태로 남는다. |
| `approver` | 실제 또는 모의 승인을 한 주체. 승인 확인 시 같은 인용 범위에 쓰인 이름이나 그 주체를 식별하는 명칭을 기입한다. |

확정에는 필요한 ID 전체가 인용 목록에 있어야 하며 자료 등급도 일치해야 한다. `actual` 범위의 확정은 모든 인용 자료가 `actual`이어야 한다. `simulation` 범위에서는 수령한 합성 자료도 사용할 수 있다. 미수령 자료를 참조한 확정, 모의 자료에만 근거한 실제 결정, 서로 다른 자료 등급을 붙인 동일 파일, 존재하지 않는 행·ID, 중복 ID는 오류다.

양사 참석, 공급사 등록, 인력 배치, 확약, 견적 승인, 설비·소프트웨어 귀속처럼 주체와 대상이 중요한 실제 사실은 인용 위치에 있는 짧은 긍정 문장 하나를 그대로 적는다. 승인·날인은 승인 주체와 완료 사실이 함께 확인되어야 한다. 요청서의 빈 승인란이나 모의 회의록만 있으면 실제 승인 결정은 보류한다. 모의 승인을 확정하면 모의 주체·결과가 적힌 원문 문장을 인용한다. 예를 들어 `모의 위원 윤봄이 장비 인수를 승인했다.`라는 인용 문장과 `윤봄`이라는 승인 주체를 함께 기록한다.

## 최소 사례

사례 루트의 `sources/표본.txt`에 아래 두 줄을 UTF-8, BOM 없음, LF 줄바꿈으로 저장한다. 마지막 줄 끝에도 LF가 있다.

```text
유형=교육용 합성 입력
세 팀이 표본 12개를 시험했다.
```

`manifest.csv`에서는 구할 서명본에도 ID를 준다.

```csv
evidence_id,kind,path,sha256,locator,issuer,required_for
SRC1,synthetic,sources/표본.txt,7bac61a8ed35138a85a379ff2d42f39cabfd15bce78a9e71f97f5f0b1b60fefe,line:2,교육 설계자,DEC1
REQ1,missing,,,,현장 계약 담당자,DEC2
```

`claims.csv`에서는 모의 입력에서 확인한 표본 수와 실제 인수 승인 보류를 나란히 기록한다.

```csv
claim_id,decision,status,scope,statement,required_evidence_ids,evidence_ids,approver
DEC1,표본수,confirmed,simulation,모의 시험 표본은 12개다.,SRC1,SRC1,
DEC2,approval,hold,actual,계약 담당자의 서명본을 받을 때까지 인수 승인 보류.,REQ1,,
```

검사 결과는 확정 1건과 보류 1건이다. `DEC2`의 미충족 ID는 `REQ1`이다. 자료가 들어오면 별도 회차에 원본, 실제 지문, 위치를 등록하고 두 대장의 개정본을 다시 검사한다. 이전 회차의 해시와 판단은 실행 기록에 보관한다.

## 해석 범위

이 검사는 선언한 의존 자료, 파일 동일성, 인용 위치, 일부 신분·승인·귀속 주장의 원문 일치를 검사한다. 숫자 계산은 해당 원장의 계산기로 재현하고, 작성자는 문맥, 제출 자격, 실제 서명 권한과 출처 진위를 원본·제공자에게 확인한다. 문장 검사는 제한된 한국어·영어 표현을 인식하므로 자유 서술만으로 민감한 판단을 숨기지 않도록 결정 유형과 실제 원고를 함께 검토한다. 변경 전 대장 지문과 원본 보관 기록을 비교하면 이미 등록한 자료와 판단 요건의 소급 수정을 확인할 수 있다.
