# 제조AI 근거 비교 실행

같은 기업에 자료를 보강한 뒤 어느 결정이 실제로 달라지는지 확인할 때 쓴다. 이 모드의 비교 단위는 **독립적으로 고정한 입력 한 세트와 그 입력만으로 작성한 1개 계획서**이다. 세트마다 최종본을 만들며 초안은 검토를 위한 한 시점의 판본이다. 일반 전체 코칭의 5관점 채점·3판 개정은 [심사 규칙](review.md)을 따른다.

## 입력 경계

각 회차에 새 폴더를 열고 원문 요청, 실제 작성 지시 전문, 허용 자료 ID·파일·SHA-256·성격(실제/합성)·제공 위치를 남긴다. 사용자가 한 요청으로 여러 회차를 지정하면 사용자 원문과 각 작성자에게 실제 전달한 회차 지시를 한 prompt.txt에서 화자와 구간으로 구분한다. 실행 뒤 문구를 만들어 채우지 않는다. 각 회차 작성자가 열 수 있는 자료는 스킬과 그 회차 허용 원문뿐이다. 평가기준의 정답·타 회차의 원고, 비교 대상 계획서는 최종본 고정 후 평가자에게만 제공한다. 독립 작성자를 둘 수 없는 경우 동일 작성자의 입력 제한 재실행으로 표시한다. 모델/도구 표시는 확인한 범위까지만 기입한다.

기초 회차는 인터뷰·원장 등 등록 자료만 사용한다. 보강 회차는 같은 기초 입력에 권한 있는 자료를 명시적으로 더한다. 시뮬레이션 자료라면 파일 자체와 출처 대장에 모두 합성이라고 쓴다. 아무 보강도 없는 기초 회차에선 실물 부족으로 막힌 의사결정, 현장 협의에 쓸 잠정 수치 선택지, 책임자와 다음 근거를 기록한다. 보강 회차에서는 신규 자료별로 채택·보류·충돌 판정을 다시 내린다. 서로의 결과를 볼 수 없는 두 회차 간 변경 이력은 최종 고정 후 평가자가 결정 ID로 결합한다.

## 회차별 실행 순서

아래 이름은 비교 모드의 스냅숏 계약이다. 입력에 맞게 계산·근거 세부 파일과 표를 추가할 수 있다. SKILL은 설치한 스킬 폴더, OUT은 이번 회차의 결과 폴더, CASE는 [증빙 규약](evidence-contract.md)에 맞춘 이번 회차의 증빙 작업 폴더로 치환한다. 출력 경로는 회차별로 분리한다.

1. **입력 동결.** 실제로 받은 원본 경로 각각에 자료 ID를 하나씩 지정한다. 명칭이 같은 파일도 ID로 구분하여 보관한다. 원문과 모형 식별자·스킬 지문은 audit/00_init/record.json에서 찾을 수 있다. 아래 예에서 I1/I2는 실제 ID로 대체한다. 출력 폴더는 새 폴더로 정한다.
2. **지표 계산.** LOT 집계 입력이 맞으면 [원장 계산](check-case.md)에 따라 CSV 열·원천·경계·목표 후보를 case.json에 매핑하고 check_case.py를 실행한다. 결과 checks.json에는 분자·분모, 기간, 자료 행·단위, 조건부/미확인을 포함한다. 지표의 원천 형식이 다르면 적합한 산식과 입력 ID/행, 계산 코드 또는 수작업 중간값을 같은 이름의 결과와 함께 보관한다. 자료 부족은 빈 값과 사유로 남긴다. 실측/추정 구분, 중복·단일 클래스와 품질-전력 비용 중복을 확인한 뒤 이 단계에서 먼저 고정한다.
3. **결정표와 단일 초안.** 모든 결정을 decisions.csv에 한 행씩 기록한다. 최소 열은 결정 ID, 과업, 근거 ID/위치와 지위, 비교 옵션, 채택·조건부·보류, 산식/범위, 실제 발주·서명 가능 여부, 후속 자료·담당, 본문/붙임 위치이다. [현장 결정과 편성](field-decisions.md)을 사용해 장마다 그 입력으로 선택할 수 있는 결과를 직접 쓴다. 별도의 소개자료나 결정표만으로 원고를 대체하지 않는다. draft.md 한 파일에 [제출 목차](submission.md)의 1~10장과 아래 붙임 4건의 내용을 합친다. 수신 자료 목록을 manifest.csv로, 주장별 근거와 승인 상태를 claims.csv로 만들어 증빙검사를 실행한다. 결정표와 주장 대장은 공통 ID로 연결한다. 출력 JSON과 두 CSV를 초안 기록에 포함하면 재검토할 수 있다.
4. **계산·붙임 검토표.** 고정된 초안을 열어 review.md에 ‘검토 ID, 검사한 원문/행·산식, 초안의 장·붙임, 기대/관찰, 판정, 수정할 내용’을 기록한다. 재검산·첨부 점검을 각각 한 항목 이상 실제 수행한다. 검사항목은 지표의 분모·기간·경계, 비용 수량×단가와 예산 잔액, 교육 인원×시간·최소 잔류, 합성/실제·상충/미수령, 네 붙임의 근거와 본문 일치, 해당 회차 공식 양식의 상태다. 근거 누락에 대한 보류도 타당한 판정이다. 수정문을 쓰기 전 검토표를 고정한다.
5. **수정과 Word.** 검토 ID별로 초안에서 바로잡은 결정·위치·남은 조건을 기록한 뒤 final.md와 final.docx를 만든다. 미해결 결정을 문서에서 감추지 않는다. 변경으로 주장 대장이나 산식이 달라졌으면 증빙검사·관련 계산을 다시 수행하고 그 결과를 최종 기록에 추가한다. [내보내기](export.md)의 Word 표·그림 검수를 수행한다. 초안/최종의 10장·네 붙임이 실제로 읽히는지, 동일 지표·금액·단위·교육·미서명 상태가 양쪽 형식에서 일치하는지 확인한다. 마지막으로 audit 체인을 검증한다.

**4개 붙임**은 ① 적용 문서 버전·쟁점·양측 결재/서명 상태를 담은 사업계획 최종합의 준비표, ② 실제·합성·미도착 자료 및 회차 서식의 대응표, ③ 자료·비용·시험·책임·일정을 연결해 따라갈 수 있는 실행 대장, ④ 승인·보류·변경 이력과 선택/조건부 서식이다. 이 네 유형은 비교용 내부 목차이며, 공식 공고의 요구 서식이 있으면 대응 위치를 표시한다. 증빙이 없는 붙임에도 어떤 결정을 누가 무엇으로 확인할지 기입한다.

스킬 위치에서 실행하는 명령 예이다. 실제 파일을 만든 단계가 끝나는 즉시 해당 add를 실행한다. 기본 원고와 자료는 OUT에 있다고 가정한다.

```sh
python3 scripts/runlog.py init "$OUT" --prompt "$OUT/prompt.txt" --model "$MODEL" --inputs "$INPUT1" "$INPUT2" --input-ids I1 I2 --depth comparison --purpose submission
python3 scripts/check_case.py --spec "$OUT/case.json" --csv "$INPUT2" --out "$OUT/checks.json"
python3 scripts/runlog.py add "$OUT" calculations "$OUT/checks.json" "$OUT/case.json"
python3 scripts/check_evidence.py "$CASE" > "$OUT/evidence-check.json"
python3 scripts/runlog.py add "$OUT" draft "$OUT/draft.md" "$OUT/decisions.csv" "$CASE/manifest.csv" "$CASE/claims.csv" "$OUT/evidence-check.json"
python3 scripts/runlog.py add "$OUT" review "$OUT/review.md"
python3 scripts/build_docx.py "$OUT/final.md" "$OUT/final.docx" --title "제조AI 사업계획서" --company "$COMPANY" --version "$REVISION" --date "$DATE" --mode submission
python3 scripts/runlog.py add "$OUT" final "$OUT/final.md" "$OUT/final.docx"
python3 scripts/runlog.py verify "$OUT"
```

검사 도구가 오류를 반환하면 해당 입력/대장의 오류를 바로잡고 통과 여부를 다시 확인한다. 검사가 정상 종료한 상태에서 남은 보류는 보고서에 유지한다. 다른 근거가 도착한 뒤 재실행할 때는 새 회차로 시작한다. 이전 판단은 원래 회차에서 조회 가능해야 한다. 순서·내용 지문은 로컬 실행의 재현 자료이며 시간 인증이나 모델 생성 증명은 아니다.

## 회차 간 판독

양쪽 final 및 검토표가 고정된 뒤에만 평가자가 계획서와 근거를 같이 읽는다. 비교표 한 행에 과업·기초 결정/근거·보강 결정/근거·변경을 가능케 한 자료 ID와 실제 지위·남은 조건·발주/제출 가능 범위를 기록한다. 설계가 보강된 경우와 증빙이 실제로 수신된 경우를 따로 집계한다. 유지·보류된 결정도 포함한다. 원문을 직접 대조한 결과와 재현 가능한 스크립트 검사, 작성자 자기검토의 판정을 구분한다.
