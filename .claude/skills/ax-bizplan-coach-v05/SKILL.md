# AX 사업계획서 코치 v0.5

## 1. 입력과 결과물 선택

대상 제도와 기업 자료를 확인한다. 제도별 교육 배점·입력 항목·과제명 규칙은 아래 파일 하나를 읽는다. 가상 기업을 새로 고르는 경우에만 references/sample-companies.md를 사용한다.

| 코드 | 제도 | 참고 파일 |
|---|---|---|
| sf | 제조AI 스마트공장 | references/program-sf.md |
| ss | 혁신 소상공인 AI 서류 | references/program-ss.md |
| ss2 | 혁신 소상공인 AI 발표 | references/program-ss2.md |
| hb | 중소기업 혁신바우처 | references/program-hb.md |

**용도**(교육형/제출 준비형)와 **개정 깊이**(간단/전체)를 독립적으로 정한다. 일반 학습은 교육형·간단이 기본이다. 선정 사례 수준의 제출안을 원하는 경우 제출 준비형·전체를 사용한다. 교육형 sf는 references/sf-quality-pack.md의 6절과 공백 제외 마크다운 5,000~6,000자를 사용한다. 제출 준비형 sf는 반드시 [제출 목차·증빙](references/submission.md)와 [현장 설계](references/engineering.md)를 읽는다. 다른 제도 제출형은 해당 서식의 표·장·별첨 순서를 따른다. 빈 서식이 없으면 실제 제출 양식 적용 여부를 ‘미확정’으로 표시한다.

사용자가 동일 제조 사례에서 자료를 추가하거나 빼고 결과가 어떻게 바뀌는지 검증하려면 [근거 비교 실행](references/comparison-run.md)을 적용한다. 회차마다 독립적으로 계산→결정표·원고→검토→개정·Word를 고정한다. 일반 제출 준비형·전체의 3판 개정과 구별하며, 모드 지정은 실행 기록에 남긴다.

제조AI 제출 준비형과 근거 비교 실행에서는 [현장 결정과 편성](references/field-decisions.md)을 읽고, [증거 채택·보류 규약](references/evidence-contract.md)에 따라 출처·주장 대장을 검사한다. 수량·예산·교육·책임 등에는 자료에서 결정 가능한 범위까지 조건부 제안과 선택 이유를 작성한다. 기준별 옵션·예상 결과·결재 전제·담당을 원고 표로 옮긴다.

사업교육, 산업안전, 보안, 양사 최종합의가 포함된 신청안은 [현장 상태와 최종판 확인](references/decision-evidence.md)에 따라 현재 판단·미확인·다음 확인 조건을 각 해당 장과 붙임에 반영한다. 제조 현장 위험이 있는 계획서는 같은 지침의 ‘비상대응을 개정본에 남기는 법’에 따라 초기 보호부터 재개 승인까지 본문에서 검토한다.

입력에 연도·회차·공고·서식이 있으면 자료명/버전/날짜/페이지를 등록한다. 확인된 공고 기준, 기존 교육 배점, 컨설턴트 가정을 분리한다. 이전 회차 한도나 비율을 새 사업의 결론으로 복사하지 않는다. 신청 전에 확보할 근거와 구축 후에야 생성되는 성능·운영 기록을 구분한다.

## 2. 기초자료와 계산

파일별 짧은 ID를 붙이고 현장 사실/합성 입력/가정/목표/계산/실측/승인을 구분한다. 주장에는 출처와 위치(행·문단·페이지), 단위·기간·책임자를 붙인다. 원장의 반복 행·기간·설비 범위와 분모를 먼저 검산한다. 품질·전력 원장이 있는 제조 사례는 [계산기 입력 예](references/check-case.md)에 따라 사례별 spec을 만들고 scripts/check_case.py를 실행한다. 열 이름은 매핑한다. 전력 자료가 없는 사례에서 계산기 요건을 맞추려고 가짜 전력을 넣지 않는다. 해당 지표만 개별 계산하고 근거를 남긴다.

원장 명칭과 조건부 지표명 또는 기간별 집계 정의가 다를 수 있으면 [기간별 지표명 대조](references/metric-scope.md)를 적용한다. 해당 이름을 사용하는 각 기간·자료·계산·본문·Word 표의 범위를 검토한다.

계획서 공통 수치는 [기준값 사전](references/values.md)에 넣는다. 재원과 지출, 품질 비용과 전력 비용이 겹치는지 확인한다. 누락은 0원이 아니다. 모든 현장 실측·원본 서명·확약·고용은 당사자 자료가 있을 때만 확인 처리한다. 증빙 대장은 건수 제한 없이 유지한다. 미수령인 항목은 담당자, 받을 파일, 확인할 결정, 기한/시점과 상태를 기재한다. 교육형은 필수 질문 한 묶음으로 진행할 수 있고 제출형은 자료가 들어올 때마다 재개한다.

## 3. 초안·심사·개정

확보한 입력을 표로 요약하고 과제명과 현장 요약 후보 5개 중 1개를 선정한다. 어떤 문제를 누가 어떤 조치로 개선하는지 한 문장으로 설명한다. [심사·개정·이력 규칙](references/review.md)을 따른다.

1. v1에는 각 장의 판단, 재계산 가능한 표와 미해결 결정을 작성한다. 제출 준비형은 요청 목록과 개념도/명세, 예산 대사, 책임·인수 절차까지 작성한다. 자료 없는 수치나 허위 실적은 채우지 않는다.
2. v1을 고정하고 가상 5개 전문 관점으로 평가한다. 17항목 설계점수와 증빙 상태를 분리한다(sf 이외에는 제도별 항목 수 사용). 평가표를 고정한 뒤 v2를 작성한다.
3. 전체 모드는 v2 재채점→반대 심사→v3 순이다. 하위 항목 3개와 치명적 결함을 우선 보강하되 같은 KPI·설비·비용이 인용된 모든 장도 함께 수정한다. 실측이 목표를 반박하면 승인 필요 상태로 전환한다. 변경 사유, 유지 근거, 증빙 미수령 항목을 남긴다.
4. 실제 사용자 프롬프트, 원입력 해시, 스킬·모델 식별자, 순서별 원고·채점 근거를 scripts/runlog.py로 기록한다. 버전명을 가려 비교할 때 한 모델의 역할 모의, 동일 작성자 재평가, 별도 검토를 구별한다. 선정 확률을 만들지 않는다.
5. [Word 내보내기](references/export.md)에 따라 최종 원고를 변환한다. 공식 양식 미적용과 실제 신청 가능 여부를 표지에 명시한다. 최종 문서는 신청자가 확인·수정하도록 제공한다.

스크립트 경로는 이 파일이 있는 디렉터리 기준이다. python-docx 의존성은 requirements.txt에 있다. 결과물은 사용자의 작업 폴더에 쓴다. 모델 성능 비교 요청에는 [격리 실험](references/benchmark.md)을 적용한다.
